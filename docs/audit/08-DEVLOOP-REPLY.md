## §3 ⭐⭐ 根因：不是「测试变多」，是**递归**【手验】

**先排除「测试变多」这个解释**：

| 日期 | 提交 | 测试文件 | 行数 |
|---|---|---|---|
| 2026-08-12 | `62d5e4b` | 69 个 | 14,556 |
| 2026-08-18 | `4006669` | 75 个 | 15,536 |

⇒ 六天涨 **6 个文件 / 980 行（+6.7%）**。⛔ **解释不了从「10 分钟够」到「10 分钟不够」。**

### 真根因

```
闸  →  跑全量 pytest（gates.sh:216）
       └─ 其中 tests/test_preflight_roster.py:70 调 run_on_commit()
          └─ 又起一个闸  →  又跑全量 pytest
                            └─ 又有 test_preflight_roster …
```

- `.devloop/gates.sh:216` — `timeout 600 python -m pytest -q`
- `tests/test_preflight_roster.py:70` — `res = gates_mod.run_on_commit(paths, "HEAD")`
- ⛔ **`grep -niE "DEVLOOP_IN_GATE|recursion|递归|嵌套"` 对两个文件 → 零命中。没有任何防递归。**

⇒ ⭐ **闸每跑一次，内部套一层，每层跑一遍完整测试。**

### 3.1 ⛔ 同一根因还解释了另一起事故

2026-08-21 用户 C 盘被撑爆：`%TEMP%` 下堆了 **2,983 个泄漏的 git 工位（≈26 GB）**
＋ pytest 临时目录 **60 GB / 一千万个以上文件**。
⭐ `run_on_commit` 每次调用建一个完整检出 —— **递归每套一层就多建一批**。

⇒ ⛔ **「闸超时」与「磁盘撑爆」是同一个 bug 的两个症状。**
⚠️ 而这个 bug 是我 2026-08-17 加 `test_preflight_roster.py` 时种下的
（那条测试的立意是对的：「判据要落在真跑上，不许读脚本文本」——⛔ 但没想到它会被闸自己跑到）。

### 3.2 ⇒ 对你 §3 改法的影响

⛔ **「实测上界 × 1.5」不适用于本例** —— 因为耗时**不是收敛的**，是递归的。
⭐ 正确的修法顺序：

1. **先断递归**（判据：闸内跑 pytest 时，`test_preflight_roster` 必须自己跳过或走非递归路径）
2. **再实测上界**（按你 §3：三次取上界，注明日期与实测值）
3. **再定预算**

⚠️ 三次实测正在跑，结果出来补进本文件 §5。
