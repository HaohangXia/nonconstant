## §1 关掉你的攻击面 #1：CLI 入口与退出码【手验】

**结论：前提成立，且比你假设的强一档。**

- CLI 入口有，**15 个子命令**：
  `dispatch / collect / halt / status / eval / autopilot / constitution / nightly / prune / audit / records / backends / doctor / gates / stats`
- 退出码**四档，不是两档**（`cli.py` 实测返回点：0×19 · 1×1 · 2×12 · 3×8）：

| 码 | 含义 |
|---|---|
| 0 | 全过 |
| 1 | 有单失败**或闸未过** |
| 2 | 输入/配置坏了 |
| ⭐ **3** | **没跑完**（撞额度 / 还有单没派）|

⭐ **第 3 档正是 spec-kit 混在一起的那个** —— 它的 `paused` 也映射成 0（你 §1-C 已证）。
⇒ DevLoop 自己把「没跑完」与「跑完了但没过」分开了，**这一档不能在转接时丢掉**。

### ⛔ 一处订正

```yaml

```
⛔ **没有 `run` 子命令。** 实际入口是 `dispatch`（派单）或 `gates`（只跑闸）。

## §3 ⛔⛔ 新增前置 P0：§5 有一个没写出来的前提，且今天不成立

你的 §5 判据是「**红检：闸判红 → 外层退出码必须非 0**」。
⭐ 判据本身对。⛔ **但它隐含一个前提：DevLoop 的闸本身是可信的。**

**【手验】2026-08-22 实跑 `devloop gates --project . --commit HEAD`：**

```
✓ 环境自检   ✓ 语法   ✓ 改动守卫   ✓ 测试守卫   ✓ 禁改清单   ✓ 被测代码来源
✗ pytest: 超时（>600s）
6 过 / 1 未过        退出码 = 1
```

**六道全绿，唯一的红是「测试跑不完」** —— 闸给全量测试 **600 秒**，而实测需要 **900~1000 秒**。

⇒ ⛔⛔ **DevLoop 今天对任何输入都会吐这一条红。**

⚠️ 这不是偶发：2026-08-19 那次无人值守真跑，`sh-1` 工人干成了（53 轮 / 35 分钟 / `worker_ok=True`），
闸判红，理由**同一条**。当时以为是那一夜的偶然，⭐ 今天证实是常态。

### ⇒ 对你 §5 的影响

> **接法完全正确，但传出去的是错话。** 包成 `shell` step，spec-kit 只会忠实地把这个假红传出去。

⭐ **建议给阶段三加一条前置**：
