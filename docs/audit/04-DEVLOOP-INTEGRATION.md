## 1.5 ⛔ 三条阻断项【全部手验】

| # | 事实 | 证据 |
|---|---|---|
| **A** | `StepStatus.SKIPPED` 是**空壳** —— 全仓仅 `workflows/base.py:24` 一处定义，**无生产者、无消费者** | `grep -rn SKIPPED --include=*.py` → **仅 1 行** |
| **B** | 自定义步骤与内建**重名 → 静默丢弃**，内建胜出，无任何警告 | `workflows/__init__.py:131` `if type_key in STEP_REGISTRY: continue` |
| **C** | 退出码只分两档，**`paused` 也算 0** | `workflows/_commands.py:1265` `return 1 if status_value in ("failed","aborted") else 0` |

**⇒ 合并后果**（推论，但基于上面三条手验事实）：

- DevLoop 的四态判定（PASS/FAIL/**SKIP**/**VOID**）进去只剩「成了/没成/停住」
  ⇒ ⛔ **「没验成」会被呈现为「成功」** —— 而那正是 DevLoop 花最大代价堵的洞
- B + C 叠加出一个真假绿：自定义闸被静默换成内建人工闸 → 无人值守时 `PAUSED` → **退出码 0**
  ⇒ ⛔ **自动闸被掉包成停摆的人工闸，而门口的灯是绿的**

## 1.6 预算/刹车无挂点【代理，未复核】

# §2 必然推出

**大前提**：DevLoop 强在验证侧（隔离/闸/台账/配额/人在环），spec-kit 强在生成侧
（一句话 → 规格 → 计划 → 任务清单）。⭐ 依据：`01-PLAN.md` 的 T2「工程价值已从生成侧
转移到验证侧」，且 spec-kit 官方工作流 `workflows/speckit/workflow.yml` 78 行里
**2 个纯人工 gate、0 个 shell step**【手验】—— 他们造了机器判定的引擎，自己一次没用。

**小前提**：DevLoop 今天卡在生成侧（§1.7，⚠️ 证据薄）。

**⇒ 结论**：最小且收益最大的第一步，是**把 spec-kit 的生成侧接到 DevLoop 的执行侧**，
⛔ **不是**把 DevLoop 的执行侧塞进 spec-kit 的引擎。

⭐ 理由（可证伪）：
- 那 16 个提示词模板是**纯 markdown、零代码依赖**【手验：grep `import`/`specify_cli` → 零命中】
  ⇒ 拿它们**不需要引擎、不需要模组、不需要碰那 161,654 行**
- 而模组那条路要绕 §1.5 的三条阻断项，⛔ 换来的控制流 DevLoop 的 `plan.toml` 已经有
（`needs` / `chain` / `parallel` / `retries` / `budget`）

⚠️ **这不推翻用户「做成模组」的决定** —— 它只是把模组**排到第三步**，
并给它加一个前置条件（§3 阶段二）。

# §3 方案：三阶段，每阶段可独立停下

## 阶段一 · 接生成侧（⭐ 零代码可先试）

拿 `templates/commands/`（10 个）+ `templates/*.md`（5 个）当提示词，
补上 DevLoop 缺的「一句话 → 任务书」这一步。

**判据**（⛔ 不是「读起来顺」）：
> **用他们的提示词生成一份任务书，DevLoop 直接吃下去、真跑一单、闸绿。**

⚠️ 预计需要几十行格式转换（他们的 `tasks.md` → DevLoop 的任务书六段式）。
⛔ 超过 100 行就说明方向错了，停下重议。

**⭐ 顺带效果**：这一步跑完就能证伪或证实 §1.7 那条薄弱推论。

## 阶段二 · 先更版本，再重测三条（⭐ 零成本，⛔ 阶段三的前置）

把 vendor 更到 **`v1.0.0`**，然后**只重测 §1.5 的 A/B/C 三条**：

| 重测什么 | 判据 |
|---|---|
| A · `SKIPPED` 还是空壳吗 | `grep -rn SKIPPED --include=*.py` 的命中数与位置 |
| B · 重名还静默丢弃吗 | 放一个 `type_key: gate` 的自定义步骤，看有没有警告 |
| C · `paused` 还映射成 0 吗 | 读退出码映射那一行 |

⛔ **不更版本就写模组 = 照着过期图纸施工。**

## 阶段三 · 最小模组（⚠️ 仅当阶段二说得通）

写**一个** step：把 DevLoop 的一整单（开工位 → 派单 → 跑闸 → 记账 → 写卷宗）
**整体包进这一步内部**。

⭐ 为什么是「一整单一步」而不是「每个零件一步」：
四态判定、三档退出码、四把刹车**全部留在这一步内部**，
⇒ ⛔ 不经过 spec-kit 那三条会丢信息的边界。

⚠️ 代价：那一步内部对 spec-kit 是**黑盒**，它的 `if`/`switch` 插不进去。
⇒ **不是「融进去」，是「并排站」。**

**判据**：
> 一份最小 `workflow.yml` 用上这个 step，`specify workflow run` 真跑起来；
> ⭐ **红检**：让那一单的闸判红 → 外层退出码**必须不是 0**。

**强制纪律**（针对 §1.5-B，⛔ 引擎不替你兜底）：
- 所有 `type_key` 加 `devloop-` 前缀
- 步骤自身启动时核对 `STEP_REGISTRY[自己的key] is self`，不是就当场判红
- 配一条测试钉死这两点
