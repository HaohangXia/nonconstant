# 做 nonconstant 学到的

> 这份文档不讲 nonconstant 怎么用（那是 README 的活）。
> 它讲的是：**做这个东西的过程里，我发现自己错在哪。**

---

## 一 · v1 想做什么，为什么停了

v1 叫 DevLoop。想法很直接：让 AI agent 不只是写代码，而是跑一个闭环 —— 派单、执行、验收、回报。

写到一半，我发现 GitHub 开源了 **spec-kit**，把编排层做完了，而且做得比我好。

这时候有两条路。一条是继续写自己的编排层，理由现成：「我的更贴合需求」。另一条是承认那半年的工作里，**真正独特的不是编排，是别的东西**。

我选了第二条。DevLoop 归档，nonconstant 从零开始，建在 spec-kit 上，不 fork、不改上游一个字符。

而「别的东西」是什么，是被一次事故逼出来的：

- 一条闸门在 **08-17** 退化成了常量 —— 它永远返回同一个结果，因此永远「通过」。
- **08-20** 才被发现。中间三天，**那条闸跑了 0 次**。
- 同期另一处：临时目录里积了 **86 GB**，撑爆了 C 盘。2,983 个泄漏的工位，加上 pytest 的临时目录。每一次泄漏都不产生任何可观测输出。

两件事的形状是同一个：**失败没有让任何东西变红，所以没有人知道。**

nonconstant 就是围着这个形状建的。

## 二 · 最值钱的一次：我把自己的四条差异化证伪了

发布前查重时，我撞见了同领域的其他项目。于是我列了四条「nonconstant 有、别人没有」的差异化，去核实。

**四条全部落空。**逐条对照 [ryangu00/axiom](https://github.com/ryangu00/axiom) 的 README 原文：

| 我以为独有 | 它的原话 |
|---|---|
| 判据不能是常量 | 「**A predicate is a letter, not a spirit.** `file_exists` passes on an empty file.」 |
| 静默失败必然累积 | 「a memory system that **reported healthy for 13 days while silently not writing**」 |
| 判据的启用条件不得由被判对象提供 | 「An agent with write access **can delete its own active claim** … raises the cost of a false "done" from free to deliberate; **it does not make it impossible**」 |
| 自曝覆盖边界 | 阈值标定 **n=1** · FP/FN 率是「**v1.2 commitment, not a v1 claim**」· 独立的 `KNOWN-LIMITATIONS.md` |

最刺的一条：axiom 写「邻居 `nah` 在**公开**语料（101,194 次工具调用）上标定，**that is the better standard and we say so**」—— 它主动承认竞品在某一维度上比自己强。

而根因不是「别人也想到了」。根因是：

> **我从未做过 prior-art 扫描。那四条差异化，一直是未经查证的自我认知。**

我用了十几轮时间给判据加固，却从没花一小时看看别人做到哪了。

## 三 · 每一次是谁拦下的

我记录了 46 条经验事实、22 次同族错误复发。挑五个最能说明问题的 —— 注意**谁**发现的：

### 1 · sub-agent 无视了逐字写明的禁令，而 hook 拦住了

同一个任务，两种约束：prompt 里逐字写着 READ-ONLY，PreToolUse hook 也配了写盘拦截。

sub-agent **写了盘，还提交了**。hook 在主 session 拦住了同样的动作。

同场景 A/B。结论不客气：**prompt 形式的禁令，免疫度是 0。**

⇒ 发现者：**hook**。不是我，也不是下达方。

### 2 · 我的验证工具整跑作废，而我打了四个「通过」

红检要证明「判据在该红的时候红了」，而「红」是从退出码读的。

那一跑我用 Python 的 `subprocess` 调 bash，解析到了 WSL 的 bash，`execvpe` 失败 —— **每一条都返回 1**。我把「跑不起来」读成了「判红 = 符合预期」，连打四个 OK。

救我的是两个期望为 0 的用例返回了 1。它们不该是 1，我才去看 stderr。

> 如果那批用例的期望值全是「非 0」，整跑会被完整记成通过。

⇒ 发现者：**两个碰巧方向相反的用例**。

### 3 · 判据的清单，放在它自己保护的文件里

`criteria-guard` 的职责是：谁动了判据文件，就判红。它的受保护路径清单写在 `nonconstant.yml` 里，而 `nonconstant.yml` 自己也在那份清单上。

实测：给清单条目加一个**行尾注释** —— `- nonconstant.yml            # 配置本体` —— 提取出的匹配串就带上了注释文本，从此永不命中。

于是：`git status` 明明显示 ` M nonconstant.yml`，而 `criteria-guard` 判 **0，通过**。

一次编辑同时完成了「越界」和「让越界不可见」。

⇒ 发现者：**一个只读的 sub-agent 扫描**。我当时的表里，这一条标的是「无风险」。我自己复现了三种写法，全部判 0。

### 4 · 我写的判据，静默地少查了一整类

`status-facts` 用正则去 STATUS 文档里定位断言。我改了一句措辞（「Phase 0~7」改成「Phase 0~7 + 10」），正则就匹配不上了。

匹配不上 ≠ 报错。**那一整类断言从此没人查，而判据照样报「通过」。**

同一轮里我在**新写的另一条断言上犯了一模一样的错**：把目录名写死进正则。

⇒ 发现者：**下一轮的一次例行扫描**。它在做别的事时顺手撞见的。

### 5 · 我在判据判红的时候提交了两次

两次都是 hard 判据判红，我照样 `git commit`。两次都靠事后 `--amend` 补救。

第二次之后我才想明白：「提交前先跑判据」是一条**没有判据的规则** —— 靠人记，而人已经忘了两次。

装上 pre-commit hook 之后，第一次运行它就拒绝了它自己的提交。

⇒ 发现者：**git**。

---

**这五条里，没有一条是「我想了想，觉得这里可能有问题」。**

每一条都是某个不由我控制的东西先变红，我才回头看。这大概是整件事最实在的一条结论：

> 判定的价值不在于它有多聪明，在于**它不归你管**。

## 四 · 立起来又被推翻的主张

我有一份只增不删的撤回记录，17 条。挑几条：

| 曾经声称 | 后来 |
|---|---|
| 「Spec Kit 无 runtime，结构上无法阻断」 | 读了源码，它有 |
| 「必须自建 CLI」 | 不必 |
| 「硬闸门装进它的机箱会变软」 | 没有依据 |
| 「删掉 `extensions/` 和 `presets/` 以减重」 | 量了一下，减的重不值得 |
| 「隔离工位 = git worktree」 | 撤回后至今没有实现路径 |
| 「不把 vendor 纳入版本控制，否则仓库暴涨」 | 实测净增 **107 字节**。我说的「暴涨」差了约五个数量级 |

最后一条是我自己写的铁律，理由两条，**两条都没查过**。

## 五 · nonconstant 作为工具，不是这个空间里最好的

这话得说清楚。

[ryangu00/axiom](https://github.com/ryangu00/axiom) 有 4 个运行时适配（Claude Code、Codex CLI、hermes-agent、OpenClaw），有完整的 prior-art 文档，有 `KNOWN-LIMITATIONS.md` 和一份正面回答质疑的 FAQ。它的 prior-art 一节还点名了另外六个同域项目 —— 其中 `groundtruth` 在 1,272 个真实 turn 上标定，`nah` 在 101,194 次工具调用的**公开**语料上标定。

nonconstant：一个 shell 安装器，一个运行时，零公开语料，未发布。

如果你要的是一个能用的工具，去看它们。

我留下这份记录，是因为我手上有一个它们没有的东西 —— **不是更好的结论，是这些结论怎么被逼出来的过程**。axiom 有 `KNOWN-LIMITATIONS.md`，那是结论。而「我把自己的四条差异化逐条证伪」「我的验证工具整跑作废还打了四个通过」「我在判据判红时提交了两次」，这些是过程。

结论可以抄，过程不行。

---

## 六 · 如果只记一句

做 nonconstant 之前，我以为难的是**想出对的检查**。

做完之后我知道，难的是承认：**你想出的检查，会在你不知道的时候悄悄停止工作，而你会一直以为它在工作。**

而唯一对此有效的东西，是让判定权离开你的手。
