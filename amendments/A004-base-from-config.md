## 3 · ⛔ 为什么当初是错的

⭐ **判定者独立了,判定的输入没有。**

```
闸比对 base → HEAD
base 由调用方提供
⇒ 被判定者可先改判据、再把 base 设成「改完之后」的状态
⇒ 差集为空 ⇒ 判绿
⇒ ⛔ 判定的输入被被判定者控制 ⇒ T1 失效
```

⇒ ⭐⭐ **T1 补强:不只判定者要独立于被判定者,判定的输入也必须。**

⚠️ P1-C4 把「谁调用」与「谁被判定」当成了两拨人 —— ⛔ 在没有编排层的形态下,这个假设**没有任何东西保证**。

## 4 · 新内容

⭐ **base 只从 `latch.yml` 的顶层 `base:` 取。**

| | 旧(P1-C4) | ⭐ 新 |
|---|---|---|
| 无参 | 工作树相对 `HEAD` | **工作树相对 `latch.yml:base`** |
| 带参 | `<base>..HEAD` | ⛔ **拒绝,退出码 2** |

⇒ `base` 落在 `latch.yml` 内 ⇒ 它受 **criteria-guard** 保护 ⇒ ⭐ **被判定者改 base = 改判据 ⇒ 当场判红。**

⚠️ ⛔ **拒绝而非静默忽略** —— 静默忽略会让调用方以为自己指定的 base 生效了(`LATCH-waiver-must-announce` 同形:静默的处置等于没有处置)。

### ⇒ **重验要求:⛔ 无。**

**理由(第一性):**⭐ 新旧在**所有已执行过的调用形态**上观察值相同 —— 无参路径行为等价(`base: HEAD`),带参路径退出码仍为 2。⇒ 已完成决定的**输入与观察值都没变**。
⚠️ 唯一的行为差异发生在**从未被执行过的路径**上:「带一个合法 ref 调用」——Phase 1/2 从未这样调过。
